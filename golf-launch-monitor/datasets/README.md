# Datasets

Data used to exercise, regress and (eventually) validate the golf launch monitor. **No dataset
here contains real measurements.** The only committed data are synthetic, generated by
software from a model.

| Folder | Contents | In git | Status |
|---|---|---|---|
| [`synthetic/`](synthetic) | `range-fixtures.jsonl`: a synthetic replay with one shot per fixture in `SYNTHETIC_FIXTURES` (`@glm/shot-pipeline`). | Committed | Generated; checked by `tests/golden` |
| [`golden-tests/`](golden-tests) | `range-fixtures.golden.json`: the summary of replaying that file through the pipeline. | Committed | Generated; checked by `tests/golden` |
| [`raw-shots/`](raw-shots/README.md) | Local captures and personal shot data | **Git-ignored** (only its README is tracked) | Empty; no capture hardware exists |
| [`calibration/`](calibration/README.md) | Calibration images and calibration records | **Git-ignored** (only its README is tracked) | Empty; calibration is Planned (Phase 2) — not implemented |
| [`reference-measurements/`](reference-measurements/README.md) | Paired readings from an independent reference launch monitor | **Not** ignored; review before committing | Empty; no reference data yet |

## Provenance labels in data files

Two independent labels travel with every shot. Neither is ever upgraded.

- **`dataOrigin`** describes the stream: `live`, `replay`, `synthetic` or `manual`. A replayed
  live recording is reported as `replay`. A synthetic or manual recording keeps its origin.
- **Per-value `source`** describes each value: `measured-camera`, `measured-radar`,
  `measured-hybrid`, `estimated-player-model`, `estimated-club-model`,
  `assumed-generic-fallback`, `manual`, `synthetic` or `unavailable`. Synthetic data is always
  `synthetic`, never `measured-*`.

See [../docs/architecture.md](../docs/architecture.md) §3.

## Formats

### Replay files (JSON Lines, UTF-8)

Defined in `packages/sensor-adapters/src/replay-format.ts`. Schemas:
`packages/shared-types/schemas/replay-header.schema.json`, `replay-record.schema.json` and
`raw-sensor-observation.schema.json`.

```
line 1     {"type":"header","formatVersion":"glm-replay-1","coordinateSystemVersion":"glm-world-1.0",
            "dataOrigin":"synthetic","createdUtc":"…","description":"…","sensorConfiguration":{…},
            "calibration":null,"syntheticTruth":[…]}
line 2..N  {"type":"observation","observation":{"sensorId":"…","sequence":0,"timestampS":0.5,"kind":"health",…}}
```

| Header field | Meaning |
|---|---|
| `formatVersion`, `coordinateSystemVersion` | Must equal this build's `REPLAY_FORMAT_VERSION` and `COORDINATE_SYSTEM_VERSION` **exactly**. A mismatch is rejected with an actionable error; files are never migrated silently. |
| `dataOrigin` | `live`, `replay`, `synthetic` or `manual` |
| `sensorConfiguration` | The recording device. For `live` / `replay` it must be `camera`, `radar` or `hybrid`; it is never `replay`. |
| `calibration` | `CalibrationRecord` or `null`. Its `coordinateSystemVersion` must match. |
| `syntheticTruth` | Ground truth per shot (position, velocity, spin, launch time, seed, flattened noise model). Allowed **only** when `dataOrigin` is `synthetic`. Consumed only by validation and tests, never by the measurement pipeline. |

Observation kinds (all in the world frame of
[../docs/coordinate-system.md](../docs/coordinate-system.md), timestamps on the session clock
in seconds):

| Kind | Content |
|---|---|
| `trigger` | Candidate impact time, trigger source and confidence |
| `ball-address` | Ball position at address; stationary, in-hitting-zone and ball-count checks |
| `ball-detection-2d` | 2D detection in one camera image. Defined in the contract; nothing produces it yet (Phase 2). |
| `ball-position-3d` | 3D ball centre with a 3×3 covariance (m²) |
| `spin` | Angular-velocity vector (rad/s) with covariance, method, quality statistics and flags |
| `health` | Sensor health report |

Parsing rules (`parseReplay`; errors are `ReplayFormatError` and name the line):

- The header appears exactly once, on line 1. Blank lines are allowed only at the end.
- Every line is validated against the shared zod schemas.
- A `live` or `replay` file may not contain `synthetic` or `manual` triggers, nor spin with
  method `synthetic`.
- Per sensor, a timestamp that goes backwards or a sequence number that does not increase
  produces a **warning**. File order is kept.
- Serialisation is canonical: parse → serialise is byte-identical (tested).
- During playback, a health, address or trigger observation more than 1 s after the current
  shot's last trigger starts a new shot (`REPLAY_SHOT_GAP_S`).

Node file I/O: `readReplayFile` and `writeReplayFile` from `@glm/sensor-adapters/node`. Writes go
to a `.partial` file first and are then renamed into place.

### `synthetic/range-fixtures.jsonl`

| Property | Value |
|---|---|
| Fixtures | `straight-driver`, `draw-driver`, `fade-driver`, `high-7-iron`, `low-7-iron`, `standard-7-iron`, `no-spin-knuckleball` (`SYNTHETIC_FIXTURES`). These are test inputs, not claims about any golfer. |
| Truth model | `createTruthPropagator`: the same RK4 physics as the simulator, default indoor environment, `premium-urethane-baseline` ball |
| Noise | `DEFAULT_SYNTHETIC_NOISE`, a deliberately clean test setting and not a model of any device: 1000 fps, 20 frames, 1 mm per-axis position σ reported honestly, no jitter, no dropouts, no outliers, spin observed with 6 rad/s per-axis σ, one ideal synthetic trigger |
| Seeds | `1000 + fixture index` |
| Sensor | `synthetic-1`, configuration version `synthetic-config-1` |
| Created | Fixed timestamp `2026-01-01T00:00:00.000Z`, so the file is reproducible |

Because truth and simulator share one physics model, this dataset tests the software (fit,
spin resolution, provenance, determinism). **It cannot validate the physics.**

### `golden-tests/range-fixtures.golden.json`

The output of `summarize()` in `scripts/datasets.ts` after replaying the synthetic file with
deterministic ids and 50 Monte Carlo samples.

- **Header fields:** `dataset`, `schemaVersion`, `coordinateSystemVersion`,
  `physicsModelVersion`, `groundModelVersion`, `estimatorVersion`, `monteCarloSamples`. The
  shot-simulator version is not in the header; the full shot records carry it in the physics tag
  `<air>+<ground>+<shot simulator>` (`LaunchState.physicsModelVersion`).
- **Per shot:** label, validity, spin mode, overall confidence, launch values, then carry
  (with p05/p95), lateral offsets, total, apex, descent angle, flight time and curve. All values
  are SI (m, m/s, rad), except the launch angles in degrees and spin in rpm, which follow the
  `LaunchState` contract.

`tests/golden` requires three things:

- the committed replay to equal the generator output byte for byte;
- every golden number to match within a relative 1e-9, with metadata matching exactly;
- two replays to be byte-identical.

The values are **model outputs, not data.** Total in particular comes from the provisional
ground model v0.2 ([../docs/terrain-model.md](../docs/terrain-model.md) §7.1 lists the fixtures'
carry and total); the no-spin knuckleball's long run-out is a known limitation of that model.

### Shot exports (`@glm/persistence`)

| Export | Format |
|---|---|
| `shotsToJson` | Envelope `{ format: "glm-shot-export", formatVersion: 1, schemaVersion, coordinateSystemVersion, exportedUtc, softwareVersion, records: ShotRecord[] }`. `parseShotExportJson` validates every record. |
| `shotsToCsv` | One row per shot. Column names carry unit and sign, e.g. `carry_m`, `carry_lateral_m_left_positive`. Optional display-unit copies. A formula-injection guard protects spreadsheets. |
| `JsonDirectoryRepository` (Node) | `<root>/players/<id>.json`, `<root>/sessions/<id>.json`, `<root>/shots/<shotId>.json`; atomic writes; validated on load |

## Regenerating

```bash
npm run datasets:generate   # rewrites synthetic/range-fixtures.jsonl and golden-tests/range-fixtures.golden.json
npm run check               # the golden test must pass afterwards
git diff datasets/          # review: every change must be explained in the commit
```

A golden diff means a model, the estimator, a fixture or the noise model changed. If simulated
numbers moved, bump the relevant model version in the same commit
([../docs/architecture.md](../docs/architecture.md) §7).

## Privacy

- `raw-shots/` and `calibration/` are git-ignored by default (`../.gitignore`), because they
  can hold personal swing data and images of the user's home.
- The parent repository's `.gitignore` also ignores `*.wav`, `*.mp3` and `*.flac` everywhere,
  so audio captures are never committed from this subtree.
- `reference-measurements/` is **not** ignored. Decide per dataset whether it may be committed
  (consent, anonymisation, device serial numbers).
- Shot records keep raw observations only when the user consents (`storeRawObservations`,
  default off).
- Nothing in this workspace uploads data.
