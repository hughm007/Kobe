# Real-footage requests — format and standing examples
When real footage would materially improve the ad, the system STOPS synthesizing and issues
a request to the owner. Format is mandatory; classification is OPTIONAL / RECOMMENDED /
REQUIRED relative to the concept being produced.

## Request format
```
FOOTAGE:        exactly what to film
WHY:            what it fixes that generation cannot
INSTRUCTIONS:   camera phone is fine; steady hands or a prop mount; landscape/portrait per ad
ANGLE:          where the camera stands
DURATION:       seconds needed (shoot 3x)
PERSON/FACE:    required or avoidable (consent + release required if a face appears)
BRANDING:       uniform/wrap/logo visibility wanted or to avoid
CLASS:          OPTIONAL / RECOMMENDED / REQUIRED
```

## Standing evidence
The first client brief in the system already identified crew POV footage as "the highest-
value missing asset - free, unfakeable, and it cannot safely be generated." Three controlled
generation tests (0 of 6 usable tool-interaction shots) independently confirmed it. Hands-on
trade mechanics route HERE by default.

## Standing request classes for any trades client
1. POV before/during/after of a real job (the "during" is the unfakeable one) — REQUIRED for
   any concept whose proof beat shows the work being done.
2. Technician rising from a finished job, wiping brow, brief natural exchange with the
   homeowner at the door — RECOMMENDED; covers the human beat the generators do worst.
3. The real van arriving/parked at a real house, wrap visible — RECOMMENDED (LB24 makes the
   generated alternative illegal anyway).
4. Owner/tech to camera, one honest sentence, no script-reading — OPTIONAL; only with
   consent and a release on file.
