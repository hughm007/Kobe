# archive/

Finished, superseded or dead work — kept, not deleted.

## Why we archive instead of deleting

The reasoning trail is the point of this workspace. A campaign that ended, a client that
left, a playbook that was replaced — each explains why things are the way they are now.
Deleting it destroys context that's expensive to rebuild and impossible to recover.

Archiving also keeps the live folders honest. A `clients/` folder listing three former
clients alongside two current ones is a folder nobody trusts.

## What to archive

- Clients whose engagement has ended
- Campaigns that have finished and been reported on
- Playbooks and templates replaced by better versions
- Research that's gone stale but might be a useful comparison later

## How

1. Move the folder or file here, keeping its original name.
2. Add a closing note beside it — `<name>-CLOSING-NOTE.md`:

```markdown
**Archived:** YYYY-MM-DD
**What this was:**
**Why it ended:**
**What was handed over:**
**What we learned:** (link to knowledge/learnings/ if written up)
**Worth revisiting if:**
```

3. Remove it from any live index — `clients/README.md`, `knowledge/index.md`.
4. Note the archival in [`../operations/worklog.md`](../operations/worklog.md).

## Before archiving a client

Run the offboarding checklist in their `access-and-accounts.md`. Archiving the folder
before access is removed and ownership transferred leaves loose ends nobody comes back for.
